# 图文操作教程

交付读者能走通的操作路径。详细程度由界面变化和决策点决定，不以字数短、截图少或评分高为目标。

## 确定目标与授权

- 明确具体任务、起始页面、前提和完成判据。优先利用用户已有背景，缺少关键输入才询问。
- 区分“读者最终要完成什么”和“助手本次获准操作到哪里”。禁止提交生产变更，不等于把完整发布教程缩成只找入口。
- 用户选择新建文档时保留旧稿；选择修改旧稿时读取当前内容再编辑，不擅自另建。
- 写教程和查看表单不自动授权提交、发布、审批、回滚或给他人发消息。保留用户已有授权。

## 1. 核验流程

优先查看实际界面和官方说明。内部平台使用可用内部知识工具或指定渠道；先找官方操作图，不为取图触发真实发布。

| 材料 | 能说明什么 | 写法 |
|---|---|---|
| 当前界面核验 | 当前入口、字段和状态 | 标注核对时间与环境 |
| 官方文档示例 | 后续流程及功能规则 | 图旁给出处，明确不是本次实际状态 |
| 说明示意图 | 定位或解释关系 | 不作为实际配置或成功证据 |

版本、变量值、比较运算符必须有依据。未知项列明“待确认内容—获取入口/负责人角色—确认后如何填写”；不猜版本，不让读者把占位符填进生产配置。

## 2. 组织完整操作链

采用“位置 → 动作 → 预期结果”，按需拆步骤，不机械重复标签。结构与来源见 [references/patterns.md](references/patterns.md)。

- 给出起始链接，再讲页面内部路径。
- 同处的简短菜单操作可合并；界面切换、表单出现、条件增加和状态改变分别说明。
- 保留关键前后图：按钮在哪里 → 点后出现什么 → 下一步点哪里。不能只展示末端下拉框。
- 相似控件写清区别，例如“条件行内的＋”与“卡片外的添加规则”。
- 表单交代字段、运算符、值、组合关系、返回值。空白表单只证明入口，不证明规则已正确配置。
- 原理、可选路线和排障放在主流程之后；主流程推荐一条可行路径。
- 分别定义演练、正式执行的结束点和成功判据；保存、审批、下发、实际命中不是同一状态。

## 3. 详细且有用的配图

- 保留必要的多图：入口、组合条件、确认弹窗、结果。不要为简短删掉导航图，也不要重复全屏图凑数。
- 使用真实截屏；不得用生成模型重建界面冒充截图。标注不能改按钮文字、配置值或布局。工具输出若改写界面内容，不能当真实截图交付。
- 官方已有清晰标注的原图可直接引用，注明来源、适用范围，示例值不可照抄。
- 裁掉无关区域，同时保留定位上下文；按需搭配入口全景和控件局部图。
- 红框框住控件，箭头指点击点，编号与正文一致。每图突出当前动作，图前必须有操作说明。
- 不上传无关个人信息或凭证；遮挡用不透明覆盖，原始敏感图也不随文上传。
- 图紧跟对应动作并带图注；参数、命令和 JSON 同时提供可复制文本。
- 按文档实际显示尺寸检查文字和箭头，不能只检查原图放大后可读。

## 4. 写入指定文档

优先用该服务工具，能力不足时按可用浏览器接口操作。云文档编辑时读取 [references/cloud-authoring.md](references/cloud-authoring.md)。

保证真实标题层级、目录与正文样式有效。核验保存和图片呈现；调用成功、上传成功不等于文档已完整保存。

## 5. 验收交付

从入口沿正文检查：控件能找到、参数有依据、结果能判读、下一步明确。未经授权的执行点只检查之前的路径；后续用有出处的官方示例，标明未实测边界。

抽检首页、最复杂操作段和执行/验证段，确认无截断、图注相邻、表格可读、目录只列章节。窄侧栏不能证明正常阅读版面；也不能仅因侧栏截断认定文档损坏。可在普通浏览器默认窗口核对，不为美化截图改变网页布局。

用户要求匿名 judge 时使用 [references/blind-review.md](references/blind-review.md)；普通交付不自动创建评审 Agent。

交付文档链接、实际完成内容及仍影响操作的缺口。没有证据不宣称已验证发布、回滚或客户端生效，不以评分代替用户验收。
